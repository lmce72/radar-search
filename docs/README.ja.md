# Radar Search

**Obsidian のノート、本文、タグ、コマンド、Web を一か所から検索。**

[简体中文](../README.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md)

すぐに調べたいときはフローティング検索、じっくり絞り込みたいときは検索ページを使えます。ホームノートへの埋め込みも可能です。Dataview やアイコン用プラグインは不要です。現在、プラグインの操作表示は中国語です。

## 主な機能

- ファイル名、本文、タグ、プロパティ、ブックマーク、内部リンク、外部リンクを検索。中国語の検索にも対応し、本文の抜粋から該当箇所へ移動できます。
- 上部のカテゴリを切り替えて結果を表示。並べ替えや、ノート・親フォルダ単位の除外ができます。
- フィルタをプリセットとして保存。フォルダ補完とよく使うルールの例を利用できます。
- フローティング検索から検索ページへ、キーワード・カテゴリ・フィルタ・並び順を引き継げます。
- コマンドと Web の検索、ライト／ダークテーマに対応。ページの結果はスクロールでき、モバイルの下部操作領域にも余白を確保します。

## インストール

**Obsidian 1.7.2 以降**が必要です。

1. [最新リリース](https://github.com/lmce72/obsidian-radar-search/releases/latest)から `main.js`、`manifest.json`、`styles.css` をダウンロードします。
2. 保管庫の設定フォルダ内の `plugins/primecore-search/` に配置します。通常は `.obsidian/plugins/primecore-search/` です。
3. 設定 → コミュニティプラグインで **Radar Search** を有効にします。

更新時はこの3ファイルを置き換え、プラグインを無効・有効にします。設定と履歴を残すには `data.json` と `history/` を保持してください。

## 使い方

コマンドパレットで **打开浮动搜索框**（フローティング検索を開く）または **打开搜索页**（検索ページを開く）を選びます。それぞれにホットキーを設定できます。リボンのアイコンはフローティング検索を開きます。Esc または外側のクリックで閉じます。スマートフォンや長時間の作業には検索ページが便利です。

左側で Vault・全体・インターネットのモードを選びます。Vault と全体検索は入力に合わせて更新され、Enter で即時検索します。インターネット検索は Enter または検索ボタンで検索先を開きます。**搜索选项** は検索オプションで、右上の歯車からプラグイン設定へ進めます。

カテゴリ名はホバーまたはキーボードフォーカスで表示されます。タッチ操作ではアイコンをタップして切り替えます。該当結果のないカテゴリは無効になり、全件空の場合は「什么都木有」と表示されます。フィルタは引き続き解除できます。

### ノートに埋め込む

次のブロックを貼り付け、閲覧ビューまたはライブプレビューで利用します。

````markdown
```primecore-search
```
````

1つのノートに複数配置できます。旧 DataviewJS スクリプトは別の入口であり、このプラグインでは更新されません。

## フィルタとプリセット

結果項目の除外アイコンから、そのノートまたは任意の親フォルダを除外できます。メニュー上部で **临时过滤**（一時フィルタ）か **写入预设**（プリセットに書き込み）を選びます。一時フィルタは現在の検索にのみ適用されます。結果ツールバーのフィルタではルールを編集でき、**保存为预设** を選ぶと名前を入力する画面に進みます。

| 例 | 対象 |
| --- | --- |
| `Projects/Archive` | 指定フォルダとその配下 |
| `path:Projects/[notes]` | 角括弧を含むパスをそのまま照合 |
| `glob:**/assets/**` | ルートを含む、すべての階層の assets フォルダ |
| `glob:**/{assets,attachments,附件}/**` | 複数の添付フォルダ名 |
| `regex:/\.(png|jpe?g|gif|webp|svg|pdf)$/i` | 大文字小文字を区別せず画像と PDF に一致 |
| `exclude:path:Work/assets` | 許可リスト内でも強制的に除外 |

1行に1ルールを書きます。`**/assets/**` は正規表現ではなく **glob** です。`*` は1つのパス要素内、`**` は複数階層に一致します。除外リストは一致項目を除外し、許可リストは一致項目のみを残します。複数ルールは「いずれかに一致」で結合されます。正規表現には `regex:` が必要です。Obsidian 標準の検索構文すべてには対応していません。不正なルールは保存前に通知されます。

設定は表と子ページで編集でき、JSON の編集は不要です。項目編集後は **应用**（適用）、親の表では **保存修改**（変更を保存）を押します。適用せず戻ると、その項目の変更は反映されません。

## データとプライバシー

設定は `data.json`、履歴は `history/` に保存され、本文索引はメモリ内に作られます。大きな保管庫の初回検索には時間がかかる場合があります。索引再構築コマンドも利用できます。履歴の日数制限は表示範囲を変更するもので、履歴ファイルを自動削除しません。

テレメトリはなく、保管庫外のファイルも読みません。**全体・インターネットモードでは、入力内容が有効な検索エンジンの候補 API に送られる場合があります。** 防ぐにはそのエンジンを無効にするか、候補 URL を空にしてください。Web 検索の実行時には検索 URL を開きます。内部表示には Obsidian の Web viewer が必要で、利用できない場合は外部ブラウザを使います。

## 問題がある場合

結果が見つからない場合は検索対象、カテゴリ、プリセット、一時フィルタを確認してください。表示の問題は標準テーマでも比較し、[Issues](https://github.com/lmce72/obsidian-radar-search/issues) にプラグインと Obsidian のバージョン、端末、テーマ、再現手順を記載してください。画像やログから個人情報を取り除いてください。

## 開発・貢献

TypeScript と Bun 1.3+ を使用します。Obsidian API はホストから提供されます。

```sh
bun install --frozen-lockfile
bun run check
bun test --timeout 5000
bun run build
```

成果物は `dist/` に生成されます。UI・検索／索引・設定・履歴はそれぞれ `src/ui/`、`src/search/`、`src/settings/`、`src/history/` にあります。専用のテスト保管庫でフローティング／ページ検索と閲覧／ライブプレビューの実際の埋め込みを確認してください。レイアウト確認は実機のタッチ検証の代わりにはなりません。

公開規則は [AGENT.MD](../AGENT.MD) を参照してください。タグと Release 名は manifest のバージョンのみ（例：`1.3.5`）とし、`v` を付けません。`bun run release:check <version>` を実行し、3つのプラグインファイルのみを公開します。
